# 抽奖与奖励配置补齐验收记录

工作树：`codex/channel-public-pool-lottery-security`。本轮在已有修改上补齐，保留其它工作区内容。验收仅使用 3001 的隔离 SQLite 和测试账号；未发布至 3000。

## 实现清单

- 通知摘要与无限分页共用查询配置，缓存键按用户及数据结构分离；领奖、通知已读共用刷新入口。
- 详情由页面布局同级抽屉呈现，管理详情按 ID 加载，查看与操作权限分别校验；普通用户和只读预览响应在服务端脱敏。
- 三处金额表单共用 `RewardAmountField` 与原始 `/api/status` 配置查询；仅 USD、quota。默认 1 USD，套餐跳过隐藏金额校验。
- 使用直接依赖 `decimal.js-light` 保留十进制字符串，四舍五入与服务端一致，实际 quota 限制为 1～2147483647。
- 拉新、公益池更新新增可选 `preserve_reward`，未修改奖励时服务端在事务锁内复用原快照；USD 保留原显示，历史人民币按保存的 quota 回显。
- 拉新表单明确次数上限、时区、激活期限、字段限制和规则摘要；源码 AST 扫描校验实际文案及 7 种语言。

## 验证边界与已有问题

- 数据与金额发放仅使用隔离 SQLite 和 `fixture-*` 测试账号；未操作真实用户、历史发奖记录或 3000。未启动 MySQL / PostgreSQL 实例做实库验收；更新继续使用现有 GORM 事务与项目锁方法，无数据库迁移。
- 批量刷新与请求拦截曾触发测试进程的静态资源 429，导致资源加载失败页。仅将隔离进程的 Web / API 限流阈值设为 10000 后继续验证，没有修改项目限流代码或其它服务。
- 发现一个既有全站语言检测问题：缓存值 `zhTW` 在刷新检测时会落入简体分支，`zh-TW` 标准标签正常。已核对 HEAD 中同样存在；本轮繁中文案以标准标签加载验证，不扩大修改全站语言切换逻辑。
- 上述验收阶段未提交、合并、推送或发布到 3000；主工作区及其它无关文件保持原样。
